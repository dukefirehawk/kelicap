# AngularDart Community Workspace Context

## 1. Overview

This repository contains the community-maintained packages for the AngularDart web framework. It consists of multiple interconnected packages structured as a monorepo utilizing Dart's Workspaces feature (Dart `>=3.10.0`).

## 2. Core Packages

- **`ngdart`**: The core, fast, and productive AngularDart web framework. Contains fundamental components, dependency injection, change detection, and core runtime logic.
- **`ngcompiler`**: The AngularDart compiler. It processes Dart components and templates at build time to generate optimized Dart code, removing the need for runtime reflection or interpretation.
- **`ngast`**: A dedicated parser and AST utilities library for analyzing AngularDart HTML template syntax.
- **`ngforms`**: A forms framework for building reactive and template-driven forms, capturing and validating user input.
- **`ngrouter`**: A routing library essential for Single Page Application (SPA) navigation and view management.
- **`ngtest`**: Testing runner and library specifically tailored for AngularDart component lifecycle testing.

## 3. Supplementary Folders

- **`examples/hello_world`**: Sample applications serving as references for AngularDart configuration and development patterns.
- **`tool`**: Likely subdirectories and scripts for monorepo utilities, CI integrations, or testing structures.
- **`goldens`**: Usually utilized for visual regression or template structure golden file testing.

## 4. Architecture & Key Workflows

1. **Compilation (AoT):** The framework relies heavily on Ahead-of-Time compilation via `ngcompiler`, coupled with the Dart `build_runner`. It parses `@Component` annotations and their HTML/CSS dependencies (using `ngast` and `analyzer`), emitting plain, highly performant Dart code.
2. **Runtime Lifecycle:** `ngdart` orchestrates dependency injection (`Injector`), view lifecycle mapping, and zone-based change detection (`NgZone`).
3. **Workspace Management:** The monorepo heavily integrates Dart Workspaces (`resolution: workspace` inside sub-packages). It leverages features expected in the Dart >= 3.10 roadmap to consolidate multiple packages under a single resolving root with Melos.

## 5. Status & Technical Debt

- **Community Maintenance**: As documented in the `README.md`, maintenance transferred from Google to the community. Related infrastructures like `ngcomponents` and `ngdart_cli` operate in discrete external repositories now, which implies potential version correlation complexities over time.

## 6. Engineering Standards

- **Code Analysis & Linting**: Built defensively upon `package:lints/recommended.yaml`, overriding basic rules to enforce rigorous static checking by turning on `strict-casts: true` and `strict-raw-types: true` in `analysis_options.yaml`.
- **Formatting**: Standardization is heavily enforced utilizing `dart format --set-exit-if-changed` in CI pipelines ensuring all contributed Dart code conforms exactly to the canonical style.
- **CI / Matrix Testing**: Continuous Integration via GitHub Actions orchestrates complex multi-environment matrix tests generated by the `melos` package. Steps are split out discretely across packages validating combinations of versions and environments (`vm` vs `browser` profiles utilizing tools like `build_runner test`).
- **Development Tooling**: Features a transition state, historically leveraging `melos` to bridge dependency resolution, which continues to provide CLI task running and pipeline generation even as workspace resolutions are updated to utilize native Dart 3 Workspaces.
